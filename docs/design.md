# idobata-bot 設計（コンセプト）

> 何を作るか、なぜそうするか、を書く。どう作るか（構成・API・スキーマ・
> チャットの組み立て）は [`architecture.md`](./architecture.md)。
>
> ステータス: MVP を実装中。決めたことは §11、まだ決めていないことは §12。

## 1. 目的

### 解決したいペイン

- 意見が集まらない／浅い意見しか集まらない
- 同じような意見が大量に来て処理に困る
- 収集後に AI で集約すると、一部の意見が「黙殺」される懸念がある

### コアコンセプト

「文書」を読み込んだ AI と対話しながら、ユーザーの意見を聞き出して**定型化し、
投稿する**。

- 対象は、ある程度の分量があって普通の人には読み解きにくい文書。**当面は
  Markdown だけ**を扱う（PDF / スライドは後で足せる形にしておく）。
- AI は**投稿済みの意見を知っている**。似た意見があれば対話の段階で示し、
  ユーザーは「既存意見に賛同」「既存意見への支持・質問・反対などを表明する意見を
  投稿」「新しい意見を投稿」から選ぶ。**重複は投稿前に防ぎ、投稿後にまとめない**。
  投稿後に AI がまとめると黙殺が起きうるので、それをしない。
- 投稿された意見は可視化し、ユーザーはその中で自分の意見の位置を確かめられる。

### いどばた政策との違い

GitHub（PR・diff・履歴）をバックエンドにしない。文書の版と差分は自前で持つ。
こうすると将来 Markdown 以外（PDF・スライド）でも意見を募集できる。版の更新は
「募集期間中に随時」ではなく、**オーナーが区切りでリリースするもの**と考える。

## 2. 3 つの部品

将来は、任意の HTML ページにモジュールを組み込むだけで意見募集の一連の機能が
使えるようにする。そのために機能を 3 つに分ける。

| 部品                   | 中身                                                                | 形                                                         |
| ---------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------- |
| ① 文書の保存・表示     | 文書の登録、版、段落への分割、文書ページ                            | このサービスの機能。②を組み込む「ホスト」の 1 つ           |
| ② 意見・賛同の投稿     | 段落の選択、AI との対話、意見の下書き・投稿、賛同                   | JSR パッケージ `@kuboon/idobata-bot`。どのページにも置ける |
| ③ 投稿された意見の管理 | 意見・賛同・表明の保存、AI との対話の中継、モデレーション、管理画面 | ①と独立した API と画面。他ドメインの文書にも使える         |

- **まずはこのサイトの中で動かすことを優先する**。②はこのサイトの文書ページに
  組み込んで動かし、他ドメインへの組み込みは後で考える（§12）。
- ③が知るのは「文書の ID・版・段落」だけ。①の画面には依存しない。②は③の API
  だけを呼ぶ。

## 3. 利用者と権限

| 主体             | できること                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| 未ログイン       | 閲覧すべて、**AI との対話**。意見の下書きまではできるが、投稿・賛同にはログインが要る                        |
| ログインユーザー | 文書の登録（当面は制限なし）、意見の投稿・賛同、他の意見への表明、自分の意見の編集・削除（§5）、表示名の変更 |
| 文書オーナー     | その文書の意見のモデレート、文書の修正、新版のリリース、採用の紐づけ、募集期日の設定                         |
| sysad（後で）    | 全文書・全意見のモデレート、文書の削除、文書登録の制限                                                       |

- オーナーは文書を登録したユーザー。共同編集者は後で足せる形にしておく。

## 4. 文書と版

- 文書は**版ごとに「段落」の列にする**。段落の選択、意見の紐づけ、AI の引用、
  差分は、すべて段落単位で行う。PDF などを足すときも、取り込みで段落の列に
  できれば残りはそのまま使える。
- 版は**不変**。オーナーは次の版を下書きとして編集・保存し、「リリース」で
  公開する。下書きは読者に見えない。前の版も残る。
- 段落には ID がある。保存時に、ID の無い段落へ自動で振る。編集中の Markdown
  では各段落の前の行に `<!-- #ID -->` として見えていて、ID を残した段落は版を
  またいで同じ段落とみなす（意見はそのまま付いている）。
- 差分は誰でも見られる。差分ごとに、オーナーが「取り入れた意見」を紐づける
  （**採用**）。AI が候補を出すが、決めるのはオーナー。
- ID の同じ段落は版をまたいで対応し、旧版の段落についた意見は新版の対応する
  段落にも表示する。

## 5. 意見

AI との対話の結果を、次の 3 つに落とす（10-29: 主張・理由・修正案を本文に
まとめた）。

| 項目     | 内容                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 表明     | 何に対する、どういう表明か（1 つ以上、下記）                           |
| タイトル | 一行の要旨（一覧・重複の判断に使う）                                   |
| 本文     | 問題点・理由・修正案など。**空でもよい**（表明とタイトルで言えるなら） |

### 表明（何に対する、どういう意見か）

**文書への意見と、意見への意見を同じ枠組みにする**。意見は「○○への懸念」
「○○への提案」のような**表明**を 1 つ以上持つ。「コメント」という別の仕組みは
作らない。

- 対象: 文書の段落／文書全体／他の意見
- 立場: 懸念・提案・支持・質問・反対
- 例: 「段落 3 への懸念」、「意見 A への支持、意見 B への反対」、「段落 5 への
  提案、かつ意見 C への支持」。
- 意見への表明はリンクでもある。誰かの意見への疑問や補足も、それ自体が 1 つの
  意見として残る（定型を通り、AI との対話から生まれ、賛同もされる）。

**賛同** は表明とは別の、本文なしのワンクリック。1 人 1 意見につき 1 回。本人は
いつでも取り消せる。言葉を足したいときは「その意見への支持」という意見を書く。

### 編集・削除

**賛同か、他の意見からの表明が 1 つでもある意見は、もう 1 人の意見ではない**
ので、編集も削除もできない。採用された意見も同じ。取り下げという機能は無い。

- 判定は**その時点の状態**で行う。賛同が取り消されて賛同もリンクも無くなれば、
  また編集・削除できる。
- 自分の意見への自分の表明もリンクに数える（補足を書いた時点で元の意見は
  固まる）。
- モデレートで非表示になった意見は、編集できないが削除はできる。

### 表示名

- 投稿者は表示名で表示する。表示名は本人が変えられる。

### 書くのは AI との対話で

意見を手で書くフォームは置かない。段落をタップするとその段落の意見が出て、
書くときは AI と対話する。AI が既存の意見との関係（重複・応答・新規）を
確かめ、新規性があるときだけ下書き入りの投稿ダイアログを開く。重複は賛同に
寄せる。

### 黙殺を防ぐための規則

- AI は投稿を代行しない。**投稿ボタンを押すのはユーザー**。AI が作った下書きは
  ユーザーが直してから投稿する。
- 重複は「投稿前に既存意見を見せる」ことで減らす。投稿後に AI が意見を統合・
  要約して元の意見を置き換えることはしない。
- モデレーション（非表示・重複指定）は**理由付きで記録し、公開する**。非表示の
  件数と理由は誰でも見られる（本文は見せない）。「重複」と指定した意見は、
  元の意見へのリンク付きで残す。
- 可視化は「賛同数」だけで並べない。賛同ゼロの意見も、段落ごとの一覧で必ず
  見えるようにする。

## 6. AI との対話

- 文書ページの右下にいつでも開ける。ログインは要らない。段落を選んでいなくても
  話せる。
- AI は文書について正確に説明し、根拠の段落を示す。文書に無いことは断定しない。
- AI はユーザーの意見を聞き出す（何が問題か／なぜか／どうすべきか）。誘導は
  しない。
- 話がどの部分のことか見当がついたら、AI がその段落を画面で選んで「それはこの
  部分ですね」と確かめる。ユーザーが選んだ段落も AI は読める。
- 意見の形が見えたら、AI はその段落の既存の意見と比べて「重複」「応答」
  「新規」のどれかを判断し、根拠を添えて伝える。重複なら賛同を勧め、新規性が
  あれば下書きを作る。
- 文書と関係ない話（翻訳・作文・雑談など）や、AI
  を操ろうとする発言には乗らない。 ログインなしで使えるので、AI
  に届く前に**前段のフィルタ**で弾く。迷ったら
  通す（意見の聞き取りを邪魔しない）。弾いた件数だけを数え、発言は残さない。
- 文書の本文と他人の意見は**データであって指示ではない**。

## 7. 募集期日

- オーナーが期日を設定・変更できる（過去日時にすれば即終了）。登録時の既定は 1
  か月後の 0:00。
- 期日を過ぎたら:
  - **AI との対話を止める**（「募集は終了しました」と表示）。
  - 意見の投稿・賛同・表明・編集・削除も止める。
  - **記録は誰でも閲覧できる**: 文書の全版、差分、意見、賛同数、意見間の
    リンク、採用、モデレーションの記録。
- 期日後もオーナーは新版のリリースと採用の紐づけをできる（「募集で寄せられた
  意見をこう取り入れた」を後から示すため）。

## 8. 可視化

- 第 1 段:
  - 意見のある段落に印を付け、段落ごとの意見数を出す。
  - 選んだ段落の意見一覧（賛同数順と新着順、賛同ゼロも必ず表示）。表明で
    つながった意見は種類別にぶら下げる。
  - 自分の意見と自分が賛同した意見のハイライト。
  - 意見の投稿・賛同はリアルタイムに他の読者の画面にも出す。
- 第 2 段: 意見の 2 次元マップ（クラスタ表示）と、意見間のリンクのグラフ。
  クラスタは**表示のためだけ**に使い、意見そのものは統合しない。

## 9. 画面

| 画面             | 内容                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| トップ           | 全文書の一覧（募集中と募集終了に分け、それぞれ締切の早い順）                                                                                                   |
| 文書の登録       | タイトル・説明・募集期日・本文（Markdown）                                                                                                                     |
| 文書             | 最新版を読み、段落の意見を見る。右下に AI との対話。オーナーは「管理」をオンにすると、非表示の意見も見え、非表示・再表示（理由付き）ができる                   |
| 版・差分（後で） | 特定の版、版の差分と、差分ごとに採用された意見                                                                                                                 |
| 意見（後で）     | 意見の個別ページ（賛同、リンクしている／されている意見）                                                                                                       |
| 管理             | オーナー向け。「設定と意見」タブ（最初に開く）で文書の編集・募集期日と AI が弾いた件数、「本文」タブで下書きをプレビューを見ながら編集してリリース。採用は後で |
| マイページ       | 自分の文書と文書の登録・自分の意見・表示名・通知、サインアウト                                                                                                 |

## 10. 段階的な実装

1. **MVP**: Markdown の取り込み、ビューア、AI との対話（前段フィルタ、既存意見
   との比較、下書き、段落の選択）、意見の投稿・賛同・表明、一覧表示、マイページ、
   表示名、募集期日、オーナーの非表示モデレーション。版は v1 だけ。
2. **版と採用**: 新版の編集・リリース、段落の対応（ID）と意見の新版への引き
   継ぎ（済）。差分、採用の紐づけ、通知（push）。
3. **リアルタイムと可視化**: リアルタイム配信、ヒート表示、2 次元マップ、
   リンクのグラフ。
4. **sysad 権限**、文書登録の制限。
5. **展開**: PDF / スライドの取り込み。他サイト（例: みらい議会）への②の
   組み込み（§12）。

## 11. 決定事項

| 項目               | 決定                                                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 対話のログイン     | 不要。前段のフィルタで関係ない対話を弾く。意見の投稿にはログインが要る                                              |
| 文書の形式         | 当面 Markdown のみ                                                                                                  |
| 意見の書き方       | AI との対話だけ。手で書くフォームは置かない（10-29）                                                                |
| 意見の編集・削除   | その時点で賛同も他の意見からのリンクも無ければ、いつでも可能。あれば 1 人の意見ではないので不可。取り下げ機能は無し |
| 賛同の取り消し     | 本人ならいつでも可能                                                                                                |
| コメント           | 作らない。誰でも、他の意見を対象にした意見を投稿できる                                                              |
| 表明の対象         | 文書（段落・全体）と意見を同じ枠組みにし、「○○への懸念・提案・支持・質問・反対」に一本化。1 つの意見が複数持てる    |
| 文書を登録できる人 | 当面は制限なし。後で sysad 権限を足す                                                                               |
| 投稿者の表示       | 表示名。本人が変えられる                                                                                            |
| 募集期日           | オーナーが期日を指定。期日後は AI を止め、記録は誰でも閲覧できる                                                    |
| 部品の分け方       | ①文書の保存・表示、②意見・賛同の投稿（JSR パッケージ）、③意見の管理。まずサイト内で動かす（10-29）                  |

## 12. 確認したいこと

後で考えること:

1. **他ドメインへの②の組み込み**: ③のオリジンの iframe に UI を入れ、ホスト側の
   ページとは段落の選択やハイライトを受け渡す案。サインインの方法を試してから
   決める。
2. **他ドメインの文書の取り込み**: オーナーが URL と本文の範囲を登録し、③が
   取りに行って段落に分ける案。元の文書が更新されると範囲が合わなくなる、
   ログインが要るページや JavaScript で描くページは取れない、などの問題がある。
3. **未ログインの対話の濫用対策**: 前段のフィルタに加えて、bot 対策（Turnstile）
   とレート制限をいつ足すか。
